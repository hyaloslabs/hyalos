# ADR-0037: Model protocol adapters and their line budget

**Status:** Accepted; `HttpTransport` reaches `https://` providers over TLS since [ADR-0039](0039-tls-to-model-providers.md)

## Context

[ADR-0016](0016-agent-runtime-and-broker-protocols.md) decides that the broker speaks Anthropic Messages and OpenAI Responses behind one adapter interface, adds the real key, removes provider-hosted tools from every request, absorbs upstream rate limits and answers terminal refusals with 402 or 403, never 429. [ADR-0004](0004-one-signed-manifest-per-job.md) puts the role and budget in the manifest, so a reader's key can refuse tools. Story S3.8 (#68) builds that interface and asks for a line budget to be set when the story is planned. This ADR records the shape, the budget and what is left out. It changes nothing those ADRs decided.

## Decision

**One relay, two thin adapters, a separate transport.** `hyalos_broker::model` has a `Relay` that every model call goes through, an `Adapter` trait for what differs between the protocols, and a `Transport` trait that carries a request upstream. An adapter is data and small functions: the paths it serves (`/v1/messages` and `/v1/messages/count_tokens`; `/v1/responses` and `/v1/responses/input_tokens`), the credential header (`x-api-key`; `authorization: Bearer`), the request headers passed on (a short allowlist; every other one, the placeholder key included, is dropped), which tool definitions the harness runs, the retryable status (529; 503) and the error shape. Path matching ignores the query string, which is passed on as sent (`/v1/messages?beta=true`). Anything else, or a method other than POST, is a 404.

**The relay's order.** A path with a space or control character is 400, as is a passed-on header value with a control character, so nothing the sandbox sends can split the upstream request. A request body over 32 MiB is 413, and one that is not a JSON object is 400. A request asking for `background` generation is 400 (`model.background_refused`): the provider would go on generating after the call returns, where no meter sees it. A reader whose request defines any tool or MCP server is 403 (`model.reader_tools`). A generation for a job whose metered tokens have reached its budget is 402 (`budget.spent`), with a message that names the budget; counting tokens is not charged and not refused. Then hosted tools are removed, the key is added and the request is sent. Refusals are written in the protocol's own error shape so the harness shows the message, and carry a `ReasonCode`.

**Hosted tools are removed by allowlist.** A tool stays only if the adapter knows the harness runs it: on Anthropic, a custom tool (no type, or `custom`) or an Anthropic-defined client tool by its exact versioned type (`bash_20250124`, `text_editor_20250728` and the others listed in the adapter), so a server tool such as `bash_code_execution_*` and a newer client version are both removed; on OpenAI, `function`, `custom`, `local_shell`, `apply_patch` and `computer_use_preview`. Everything else, including a type this build has never seen, is removed, so a new hosted tool fails closed. `mcp_servers` is always removed. If no tool is left, `tools`, `tool_choice` and `parallel_tool_calls` go too; if some are left, a `tool_choice` naming a removed tool goes; on OpenAI, `include` entries asking for a hosted tool's output go. The request stays one the provider accepts.

**Busy is retried, then answered retryably.** Upstream 429, 502, 503, 504 and 529, and a provider that could not be reached (`transport.unreachable`: nothing was sent), are retried up to four calls in all, waiting the provider's `retry-after` or 1, 2 and 4 seconds, never more than 30. If the last call is still busy, the broker answers 529 (Anthropic) or 503 (OpenAI), which the harnesses retry. An OpenAI 429 whose error is `insufficient_quota` is a spent key, not a busy provider, and is answered 402 at once. Other upstream statuses pass through unchanged. Any other transport error happened after the request was sent, when the provider may already be generating, so it is answered 502 at once rather than paid for twice.

**Metering reads what the provider reports.** A successful generation's body passes to the harness unchanged while the relay reads its usage: the whole JSON document, or each server-sent `data:` line. Input is `input_tokens` plus Anthropic's cache creation and cache read tokens (or `prompt_tokens`), output is `output_tokens` (or `completion_tokens`); streamed events repeat running totals, so each keeps its largest value. The job is charged when the body ends or is dropped part way. A response can take a job past its budget; the next call is refused. **Metering fails closed:** a successful generation whose body reported no usage, or whose usage could not be read in full (a JSON document or event line over 32 MiB, JSON that does not parse, a stream dropped before its usage arrived), is charged the job's whole budget. OpenAI's `response.completed` echoes the request's instructions and tools, so its line can be large and is read whole. A local server that reports no usage therefore gives a job one call.

**The transport in this build is plain HTTP to loopback.** `HttpTransport` speaks HTTP/1.1 (`connection: close`, `accept-encoding: identity`, chunked or sized bodies) to `localhost`, `127.0.0.1` or `[::1]` only, because it carries the key in clear. That is enough for a local OpenAI-compatible server (Ollama, vLLM). An `https://` base is refused (`transport.tls_unavailable`): a TLS client in the trusted core is a dependency decision for its own ADR, with the story that first calls a provider on the internet. A header or target with a control character or space is refused before anything is sent.

**The line budget for `core/broker/src/model/` is 1,200 counted lines** (non-blank, non-comment, outside test modules, as `cargo xtask lines` counts). The first version is about 880. `cargo xtask lines` reports the part and fails if it passes its budget, so growing it is a reviewed change to the table in `crates/xtask`. Code that adds TLS, a model allowlist or content gating either fits inside it or comes with a new budget in its own ADR.

## Consequences

Both adapters pass one contract suite (`core/broker/tests/model.rs`) covering key injection, per-job metering, refusing a reader's tools, removing hosted tools from every request, retry and the retryable status, and the query string; a local server test runs the OpenAI adapter over real TCP. A third protocol is another small `Adapter` and the same suite.

Not here: reserving spend for calls in flight or capping `max_tokens` to what is left, so parallel streams cannot all pass the budget check (S3.2); a deadline on the whole response rather than on each read; the sandbox-facing socket that turns a harness's HTTP into a `Request`, wiring the relay into the broker's job table and dropping a job's meter at `end_job` (S3.2), TLS, which models a job may use (a model allowlist or mapping, spike #72), reporting spend to the engine, and content-gating tainted output (S4.5). An adapter that misjudges a client tool as hosted makes the harness lose that tool, which is the safe direction.
