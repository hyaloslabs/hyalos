# ADR-0016: Agent runtime, broker protocols and model credentials

**Status:** Proposed

## Context

Walking one real job end to end ("From Claude Code, I ask Hyalos to fix issue #42 in my GitHub repo and open a PR", see `docs/planning/reference-job-walk.md`) showed that no ADR says what runs inside a sandbox, how a tool with no network reaches the broker, which model protocols the broker speaks, or who holds the model credential.

Today's hivrr already ran Claude Code in worker containers with `ANTHROPIC_BASE_URL` pointed at its own proxy, a placeholder key in the container and the real key added outside. It ran readers with `--tools ""`. That path is proven, but with network access; the loopback forwarder below is new.

## Decision

**Readers and planners.** A reader needs no sandbox ([ADR-0005](0005-provenance-is-a-type.md), [ADR-0002](0002-one-binary-two-processes-sandboxes.md)). A planner that needs read access to the code runs in a sandbox with read-only tools, as an actor variant.

**Actors run any harness through one contract.** Inside the sandbox, a small forwarder listens on a loopback port and relays to the broker's channel ([ADR-0011](0011-pluggable-substrates.md)). The harness sets its base URL to that port with a placeholder key; the broker adds the real credential. v1 supports Claude Code, Codex, and the two providers' Agent SDKs. Any other runtime that honors a base-URL override works too. A harness sends tool definitions on every request, so it can only be an actor or deterministic step, never a reader.

**The broker speaks two protocols in v1:** Anthropic Messages and OpenAI Responses. The OpenAI-compatible format also covers local models (Ollama, vLLM). Both sit behind one adapter interface to stay inside the trusted-core line budget.

**Harness traffic other than model calls is off by default** (telemetry, auto-update, built-in web fetch). Anything needed goes through the egress allowlist. The sandbox image sets this for each harness. Claude Code gets `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_AUTOUPDATER`, `DISABLE_TELEMETRY` and `DISABLE_ERROR_REPORTING` set to 1, and `--tools` limited to the tools the step needs. Codex gets `analytics.enabled=false` and `web_search=disabled`. A spike showed that without these Claude Code looks up `api.anthropic.com` directly despite its base URL, and Codex retries a tracking host for about five seconds at startup. The Claude Agent SDK takes the Claude Code variables, and the OpenAI Agents SDK needs `OPENAI_AGENTS_DISABLE_TRACING=1` because it exports traces to `api.openai.com` by default. Codex runs in `danger-full-access` mode inside the container, which is the boundary; its own sandbox also works with `sandbox_workspace_write.network_access=true` but blocks loopback otherwise. These settings were verified on Claude Code 2.1.316, Codex 0.114.0, Claude Agent SDK 0.3.316 and OpenAI Agents SDK 0.21.0, so the image pins those versions and rechecks the settings when one changes.

**The broker removes provider-hosted tools from model requests** (web search, file search, code interpreter, hosted MCP) and passes only tools the harness runs itself, because no manifest grants a hosted tool and the broker enforces the manifest ([ADR-0004](0004-one-signed-manifest-per-job.md)). The provider runs a hosted tool outside the sandbox's network, and a query string can carry data out, so the harness's own setting is not relied on. A spike showed that removing a hosted tool leaves the request valid on both APIs and the harness still completes its task. A harness can make the hosted-tool request separately (Claude Code's web search does), so the broker removes them on every request.

**Needed non-model traffic goes through the broker as an allowlisting proxy.** The sandbox sets `HTTPS_PROXY` and `HTTP_PROXY` to the forwarder port and `NO_PROXY=127.0.0.1,localhost`, so model calls keep the direct channel. The broker refuses a CONNECT or HTTP request to any host outside the manifest's egress hosts, IP literals included. Claude Code's web fetch checks each domain against `api.anthropic.com` first. That host must stay off the allowlist, because it would give a prompt-injected agent a route to an attacker's Anthropic account, so the image sets `skipWebFetchPreflight` for steps that enable web fetch.

**The broker uses status codes the harnesses handle.** A terminal refusal (budget exhausted, a manifest refusal) is 402 or 403 with a clear message. It is never 429: Claude Code keeps retrying a 429 with backoff (it was still retrying after 45 seconds in the spike), and Codex gives up on any 429 and drops the message. The broker absorbs upstream rate limits and overload itself, retrying with backoff. If it gives up, it returns the provider's own retryable status (529 on the Anthropic adapter, 503 on the OpenAI adapter), which both harnesses retry.

**Typed results from a sandboxed harness.** A harness returns its result by running a small `hyalos-submit` helper that ships in the sandbox image. The helper posts the result through the forwarder to the broker, which validates it against the step's schema: size and depth caps, unknown fields rejected, and no unbounded free-text fields. Strings are bounded and constrained, and any string derived from tainted input stays tainted and reaches an actor only through a gated handle. The broker hands the engine only the typed values. The harness's chat output is discarded, and a missing or invalid submission fails the job. This works with any runtime that can run a command, and it does not couple the broker to each provider's tool-call format. A **planner** is an actor variant with a read-only repository mount, no push action and no egress except the broker, and it returns its plan this way.

**Model credentials.** v1 default: API keys held by the broker, as in [ADR-0002](0002-one-binary-two-processes-sandboxes.md). The broker never stores or injects a subscription token.

**Subscription mode (experimental flag).** The vendor's own unmodified client (Claude Code or Codex) signs in inside the sandbox with the user's own token. The broker does not handle it. It is recorded on the job event as a weaker tier, "credential inside sandbox," and is limited to jobs with no tainted input. Under [ADR-0005](0005-provenance-is-a-type.md), any actor that reads forge-authored content (issue text or repository files) runs tainted, so no harness job that reads the repository qualifies today: the mode is effectively disabled until the exfiltration risk is better bounded or a narrower trusted-repo setting is defined. Provider token formats are also added to the broker's content gate, but only as defense in depth: a pattern match cannot stop an agent that encodes or splits a token. The mode ships only after Anthropic and OpenAI answer whether this use is permitted.

## Consequences

The sandbox image gains a forwarder and the `hyalos-submit` helper; a spike with a real harness is the M1 gate, because "no secrets in the sandbox" only means something if a real agent is working there. Two protocol adapters count against the 30,000-line budget. If the providers say subscription mode is not permitted, it is removed without touching anything else. A subscription token in the sandbox can leave through any permitted output, so it stays restricted to untainted jobs, which today means no job that reads repository files, until that risk is better bounded.
