# ADR-0038: Model calls from the sandbox, and the provider key file

**Status:** Accepted

## Context

[ADR-0002](0002-one-binary-two-processes-sandboxes.md) decides that the broker holds the provider API keys and makes every model call, and that v1 bounds the loss with a dedicated key, a provider-side spend cap and per-job metering. [ADR-0016](0016-agent-runtime-and-broker-protocols.md) puts a forwarder in the sandbox that relays the harness's calls to the broker's socket, which a substrate mounts at `/run/broker.sock` ([ADR-0032](0032-the-substrate-interface-and-its-contract.md)). [ADR-0037](0037-model-protocol-adapters-and-their-line-budget.md) builds the relay that adds the key and meters each call. [ADR-0035](0035-the-private-channel-between-engine-and-broker.md) left open where the broker gets its keys (it starts with an empty environment), how it knows which job a call from a sandbox belongs to, and the socket the sandbox reaches. Story S3.2 (#17) needs all three. It also needs calls side by side to stop passing a budget together, which the review of ADR-0037 found.

## Decision

**The broker reads the provider key file itself.** The operator writes `provider.keys` in the config directory: `name = value` lines for `anthropic.key`, `anthropic.base`, `openai.key` and `openai.base`, with `#` comments. A base defaults to the provider's public API. The engine starts the broker as `hyalos broker <socket> [<provider.keys>]`, passing the path and nothing else. The path is not a secret, but the file is, so the broker reads it with the same checks as `engine.key` ([ADR-0030](0030-hardening-the-engines-key-owner-and-core-dumps.md)): a regular file, owned by the effective user, closed to group and others, at most 16 KiB. A file that fails those checks or does not parse stops the broker, and an error names the line or the provider, never a value. A missing file means no provider yet: the broker runs, and model calls are refused with 403 `model.no_provider`. The keys never pass through the engine or the channel. A provider whose base this build cannot reach (an `https://` base until TLS, #159) is refused the same way, with the transport's code.

**Each job has its own socket, and the socket is the job's identity.** For each job, the engine makes a directory in its runtime directory with a name drawn from the operating system (`hyalos-job-` and 32 hex characters, mode 0711, refused if it exists). It sends the socket path in that directory to the broker in `start_job`, which gains a `socket` field. The wire protocol becomes version 2. The path comes over the channel and not on the command line, because the command line is readable by every local user and knowing the path is what lets a process reach the socket. When admission succeeds, the broker listens at that path and makes the socket connectable by any user (0666), because the sandbox runs as another user. The directory can be entered but not listed, so its random name is what keeps other local users out. If the socket cannot be made (the path exists, is relative, or is longer than 100 bytes), the job is refused with `broker.socket_unavailable`. Nothing in the sandbox is a credential: the harness keeps its own placeholder key, and the broker drops it. `end_job` stops the listener, removes the socket and forgets the job's meter; a call still open is refused with 403 `admission.ended` before it reaches a provider, or its stream is cut off, and what it settles afterwards is not charged to the forgotten job. Dropping a `JobDir` removes the directory.

**The sandbox speaks plain HTTP/1.1 on the socket, one call per connection.** The broker reads a request line, at most 100 headers in 16 KiB, and a body of `content-length` bytes up to 32 MiB. A chunked request body is 411. The broker answers with `connection: close` and writes the body as it arrives, so a stream reaches the harness as it is generated. A path under `/v1/messages` goes to the Anthropic relay and one under `/v1/responses` to the OpenAI relay; anything else is 404. A job may have 16 calls open at once; another connection is closed unanswered.

**The manifest is checked on every call.** A call after the manifest's deadline is 403 `admission.expired`, in the protocol's error shape. A reader's tools are 403, and a spent budget is 402 naming it (ADR-0037). None of these is ever a 429. Claude Code and Codex fail a job promptly on 402 and 403 and show the broker's message: spike #72 measured both, and the tests pin the exact statuses and error shapes the broker sends. So this is not run against the real harnesses in CI, which would need real keys.

**Calls in flight hold the output they may produce.** Before a generation is sent, it holds what it asked for in its output limit (`max_tokens` or `max_output_tokens`, or 16,384 when it asked for none), capped to what is left of the budget after what is spent and what other calls hold. The request is rewritten to ask for no more than it holds. When the call ends, its hold is released and its reported usage charged; a refused or failed call releases its hold and charges nothing. A call that finds the budget spent is 402. A call that finds the rest held by calls in flight is told to try again, with 529 (Anthropic) or 503 (OpenAI) and code `budget.held`, because those calls will release what they do not use. Input tokens are not held, so calls side by side can still pass a budget by their input, but not by their output.

## Consequences

An end-to-end test runs the real broker binary with a key file pointing at a local OpenAI-compatible server. A harness, started by the local-process substrate with only a placeholder key, calls the model through its job's socket. The test then scans the harness's environment, everything it wrote and a dump of its own memory for the key. The key is drawn at run time so it is in no binary, and the test checks that the scan can see what it looks for. The container substrate is not used for this test, because no harness image exists yet (S2.9).

`launch_self` now takes the key file's path. Still not here: a command that starts the engine and calls it; the forwarder and `hyalos-submit` in the sandbox image (S2.9); TLS to providers on the internet (#159); restricting who may connect by peer credentials, which differ by substrate (a rootless runtime maps the sandbox user to a subordinate id); a model allowlist; and reporting spend to the engine.
