# ADR-0036: The simulated world and the log scan

**Status:** Accepted

## Context

[ADR-0013](0013-deterministic-simulation-and-evidence-gated-releases.md) decides that the engine runs under a fake clock, a fake substrate and seeded randomness, and that a simulated run fakes the forge and the model provider too, so a failing run replays from its seed. `crates/sim` gives a fake clock and one random stream per boundary, but nothing yet stands on those streams: there is no fake forge, model provider or substrate driven by them, and no simulated job. [ADR-0003](0003-event-log-is-the-database.md) decides that events hold digests and typed values, never content, so the log carries no credential, token, provider key, raw model text or raw forge content. That is true of the event types; nothing yet shows it is true of a run. This ADR adds both for stories S1.5 and S1.1. It changes nothing those ADRs decided.

## Decision

**The world is a crate of its own, `crates/world`.** It depends on the engine, log, policy, broker and substrate crates and on `hyalos-sim`. It is not in `hyalos-sim` because the engine's tests already use `hyalos-sim`, and a simulator that depends on the engine would make the two depend on each other. It is not trusted core and the binary does not link it.

**Four fakes, each on its own stream.** A fake forge (read an issue, open a pull request), a fake model provider (a reply and a token count), a fake substrate (`SeededSubstrate`, which starts no process and decides at the start how the sandbox will end) and a seeded gate (allow, deny, unknown, a fault, or too slow for its deadline). Each draws only from the stream named for it (`forge`, `model`, `substrate`, `gate`, with `order` for the runner's own choices) and takes time only from the fake clock, so extra draws on one cannot change what another does (ADR-0013). Failure rates are fixed in the code and chosen so that every path occurs within 150 seeds. The fake forge and the fake model each refuse a token or key that is not the one they hold, so a run that handed the sandbox's placeholder to a boundary would fail. The `Forge` and `Model` traits are defined in this crate. When the broker's real adapters exist (ADR-0016) the traits move to where they are used, and the fakes implement them there.

**A runner drives one job end to end.** `run_job(seed, dir)` opens a real engine on a real log, has a human approve an operator policy, creates a task and a job, mints a manifest through `Engine::mint_manifest`, and admits it through the broker's `Admission`. It starts a sandbox on the fake substrate with only a placeholder credential in its environment, then does three to ten steps, each admitted again so that an expired manifest authorizes nothing: read an issue (a gate asks about the content), call the model with everything read so far, ask the egress gate about a host, or open a pull request. A job that spends more tokens than its manifest allows fails. A gate that answers unknown, errors or is late holds the task through `Engine::rule_gate`. The sandbox's ending decides the job otherwise. The sandbox does no work of its own: the runner stands in for the sandbox's calls and the broker's handling of them, in one process, because the sandbox-facing socket does not exist yet.

**Every run checks itself.** Before `run_job` returns, the state must hold the properties of ADR-0009 (`State::invariant_violations`), a replay of the log must give the state the engine holds, and the log must verify against the engine's public key. A seed that breaks any of them is an error naming the seed.

**Five strings are planted in every run and scanned for.** For the seed, `Fixtures` holds a forge token and a provider key (held only by the fake forge and the fake model, as the broker would hold them), a job credential (the placeholder in the sandbox's environment), raw forge content (an issue body that tries to give the model instructions), and raw model text. They are unique to the seed and none is a part of another. `scan` searches every file in the run's directory, the database, its write-ahead log and anything beside them, for each one as raw bytes, so a string in a payload, a column or a freed page counts. The tests require that forge content did reach the model in the runs scanned, and that the scan finds each string in a file that holds it, so a clean scan is not clean because nothing was planted or nothing was looked for.

**What this shows and what it does not.** It shows that along the real path from request to the end of the task, with the real engine, log, policy, manifest and admission, nothing planted reaches the file. It does not show the same of the real broker or a real sandbox, which are not built; of a string encoded or split (the scan is for the plain bytes); or of a model that tries to put a secret into a field. The last is the types' job: the only strings in an event are reason codes (ADR-0035), and the tests of those are where that is shown.

## Consequences

A failing simulated run is reproduced by its seed and a directory. Each run writes a real database, so about 150 runs take several seconds. The world gives S1.1 its last box and S1.5 its last box, and is where later stories put what they add: the red-team corpus (S8), faults in the substrate and broker, and the real adapters when they exist. The fault rates are a judgement, and a change to one changes which seeds hit which path. Nothing here replaces the contract suites, which carry the claims about real isolation (ADR-0032), or the chaos scenarios.
